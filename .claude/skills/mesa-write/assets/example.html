Private storage for document uploads in staging

Prepared for Sample Client (sample data)
 November 3, 2026Version 1.0Ready for review

Summary

Staging needs a private place to store the documents users upload, so the team can test the upload flow end to end before it reaches production. We propose one private S3 bucket with encryption, versioning and a 30-day cleanup rule, created through the existing Terraform setup and reviewed like any other change.

1. Context

Uploads in staging currently go to a shared development bucket that other projects also use. That makes test data hard to clean up and means access is broader than it needs to be.

2. Proposal

A dedicated bucket for this project, private by default, readable and writable only by the staging application.

SettingValueWhy
AccessPrivate, application role onlyNo public links; uploads are personal documents
EncryptionServer-side (S3 managed keys)Encrypted at rest with no key management overhead
VersioningOnRecovers files overwritten or deleted by mistake
CleanupDelete objects after 30 daysKeeps staging small and test data short-lived

4. Risks

  • If staging ever stores real customer documents, 30 days may be too long; we would shorten it.
  • The application role needs one new permission. It is limited to this bucket.
