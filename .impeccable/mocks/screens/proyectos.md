# proyectos — open PRs per GitHub Project (t152)
What: one screen per client project, where a project is a GitHub Project v2 board (DRE-RMS-backlog = 7-Arrow/projects/2, the 4 dre-* repos; Prospec = designli/projects/45, the 3 prospec-* repos). Every open PR of those repos is listed, the team's included, with its status, its board issue (with the issue's Status) and its Mesa ticket. Project tabs sit under the title; "Abrir el board en GitHub" is the only outbound action; the sync note reads "Leído de GitHub · hace 2 min".
Band grammar (Mapa de metro): stations = the board's Status columns, each with "N issues · M PRs" (quiet stations "sin PRs" are dimmed, "Sin estado" is dashed). One GitHub-red line per repo, told apart by the label at the left edge, never by hue. A tick on a line = one PR; a filled tick = te toca (no review of his yet, or his own PR); a dashed tick = draft. An interchange ring + ink connector = one issue with PRs in two repos (GHI-484: dre-backend #490 + dre-frontend #610). A short ink bar over a tick = open blocker in his Mesa review. A spur line "Sin issue" branches off the lowest line and carries the PRs that hang from no issue. A dashed "Tren a staging" track carries the bot's "Create staging PR" release PRs (one per repo, they ask for no review). The selected station gets a thick capsule and an ink underline; the other stations dim to 35%.
List under the band: default is the station where something is his; if nothing is, the station with the most PRs (decided 2026-11-13, 2A). Header "<station> · N issues con PRs abiertas · M PRs · K bloqueante tuyo" and three tabs: Esta estación, Todo el proyecto, Te tocan. Grouped by issue (ring or dot, GHI-n / #n, title, "N PRs · repos", the issue's board Status as an ink pill, dashed when "Sin estado"), PRs hang under it on a rule stub. Columns: Issue y PR (title, author, age), Repo, Checks (pasan / corriendo / fallan 1 de 4 / conflictos), Review en GitHub (Aprobada / Cambios pedidos / Review pendiente), Tu review en Mesa (Aprobaste · sin merge / 1 bloqueante / Sin tu review / Tuya, plus Borrador), Ticket (Mesa ticket chip in Claude orange, or "sin ticket"). The selected row is raised.
States (mock bar, one button each): DRE · estación (default); Sin issue (spur: "Te tocan" first, capped at 3 + "N más que te tocan", release v1.15.0 as one group, "Aprobaste, sin merge" folded behind "Ver las 7"); Prospec (issue in QA, PR with no issue, "Tren a staging" as a dashed group with a link to GitHub); Sin PRs (empty project: dimmed lines, "Prospec no tiene PRs abiertas", last merged PR, links to the board and the other project); GitHub limitado (Estados B: the rail gets the "Fuentes" block with GitHub cut by a slash, a note under the title "GitHub en pausa hasta las 11:05", lines go dotted, rows say "Dato de las 10:38" and "sin datos"; no alert). Many PRs: every group and station caps visible rows and ends with "N más" or "Ver las N".
Phone 390x844 (Teléfono A parity, tab bar Hoy · Tablero · Tickets · Salidas · Proyectos): three frames. 1 Proyecto: project tabs, the band collapsed to the corridor of the selected station (neighbours named at the edges), station tabs that scroll, issues and PRs as two-line rows. 2 Una PR: full screen, Estado (blocker quote, checks, conflicts), Issue en el board, Ticket en Mesa, docked actions Abrir en GitHub (56px) | Ver ticket | Revisar de nuevo; the content ends above the dock, nothing sits under it. 3 Sin issue: "Te tocan" first, the rest folded.
Lines carry source only: every PR line is GitHub red; repos are never colour-coded; no red/green status colours; checks, reviews and blockers are told by icon and text. No tag is solid ink here: "te toca" is told by the filled tick and the "Sin tu review" / "Tuya" tags.
Must not change: Mesa never writes to a client's GitHub Project (read-only, t10 rule); the Mesa ticket chip is the only Claude-orange mark; --mute for secondary text.
Data map (for the build): repos = config/sweep.json githubRepos (7); board Status columns: DRE = Blocked, To-do, Copied to Dev Jira, In Development, In QA, Approved by QA, Ready for UAT, Approved, Done; Prospec = Backlog, Todo, Blocked, In Development, Pending PR approval, Ready for QA, In QA, Ready for UAT, Done. Mesa side: reviews + review_findings, fetchPrDetail (src/lib/integrations/github-ingest.ts:96), ticket <-> PR through reviews.ticket_id and ticket_refs. The build needs a REST read of open PRs per repo, Project items with Status and linked PRs (`gh project item-list` works; GraphQL is shared with pr-monitor and rate limited), and a project -> repos map in config. Checks, conflicts and GitHub review decisions are not in Mesa today.
Devs: the rail Proyectos count = open PRs across projects (31 = 26 + 5). The mock bar switches views and themes; `?v=desk|spur|prospec|empty|limit|phone&theme=dark` also works.
Datos de muestra: PRs, issues, board statuses, Mesa reviews and tickets are real as of 2026-11-13; checks, conflicts, GitHub review decisions, the outage and the empty Prospec are sample.
